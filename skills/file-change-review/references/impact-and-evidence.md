# 功能丢失、用户影响和问题证据

在能力删除/替代、分支收窄、消费者迁移，或发现问题/隐患、证据争议时读取。普通对照和验证遵循入口即可。

## 功能是否丢失

读取基线、当前实现与消费者，检查入口、公开能力、关键分支、副作用及服务的用户/工程场景。新增文件改前职责写“改前不存在”。重点看整文件删除、重命名/拆分/合并、导出/路由移除、分支收窄、fallback/错误处理删除、平台缺边、注册消失、测试覆盖减少。

| 固定结论 | 所需依据 |
| --- | --- |
| 否 | 原能力仍可达，或等价实现完整承接消费者；文件删除不代表功能消失 |
| 是（按需求移除） | 能力确实移除且需求明确要求，仍写“是”，但不自动构成 finding |
| 是（移除意图待确认） | 能力确定消失但无明确需求依据 |
| 是（非预期丢失） | 应保留能力被破坏，关联 finding |
| 高疑似 | 有可达风险但关键替代/消费者或环境证据未闭合 |
| 证据不足 | 基线、消费者或替代不可确认，不凭文件名或删除行数断言 |
| 不适用（新增文件） | 基线不存在文件 |

## 用户影响与问题画像

- 由入口和消费者确定角色/账号/权限、开关/数据/网络/缓存条件，页面/操作、平台/版本/地区/实验范围，直接用户结果及状态/持久化/网络/埋点/推送/后台/构建发布等间接结果。
- 不受影响须有反向依赖或执行链证据，“未改文件”“仅内部改动”“影响小”不是依据；内部改动说明用户表象为何保持不变。
- 隐患须解释当前 diff 如何引入、放大或暴露可达风险，列条件、用户现象、范围、可恢复性和缺口；旧问题同时存在不证明归因，无可达链的未来担忧不列当前隐患。
- 每项问题画像：`谁，在什么前提下，做什么后，实际/可能看到什么；正常应该是什么；影响是否可恢复`。函数名、状态值、日志只作证据，不作用户现象。
- 未有实际用户异常证据写“尚未确认用户问题；已发现……风险”。仅埋点或后台一致性写“前台无明显表现”和数据影响。
- 没有确认隐患写“未发现确认隐患”，仍分别保留高疑似、猜测和未验证边界，不制造风险。

## 证据等级与频率

| 证据等级 | 判定 |
| --- | --- |
| 运行实锤 | 声明的真实运行环境已发生，有可核对截图、录屏、日志或数据 |
| 测试实锤 | 确定性测试/脚本复现条件和结果，不外推真实用户结果 |
| 代码实锤 | 实际入口到结果静态链闭合，仍标运行待验证 |
| 高疑似 | 静态链基本闭合、条件可达，但缺独立 Oracle、运行样本或关键环境 |
| 猜测 | 仅有信号，条件、链路或结果至少缺一环，写缺口与最小补证据动作 |
| 待确认 | 证据不足、矛盾或无可靠基线 |

频率独立判断：`稳定复现` 须控制关键条件并在声明环境重复触发，记录环境和重复证据；`偶现` 至少一次真实发生样本但同样步骤不能稳定重复，写未控制的时序/环境/外部因素；其余 `频率待确认`。代码实锤可配频率待确认，运行实锤可配偶现；无样本的竞态不是偶现，测试稳定复现须限定测试环境。

相关性不是根因；无引入前后对比时回归与否写未知。P0–P3 须有明确条件、实际影响和可达位置，不自动构成合并门禁。

## 验证与复现

每个用户可感知功能点即使无 finding 也给验证：版本/平台/账号/权限/数据/网络/缓存/开关等前提；入口和动作；改前预期；改后预期与不变行为；UI、交互、网络、持久化、埋点或后台 Oracle；已实测/自动化覆盖/静态推导/待验证。仅在基线成立时写“改前无此能力”，必要时同条件对比新旧版本。

每项 finding 复现绑定 P?：前提、入口、顺序动作、实际/预期结果、Oracle、复现类型、稳定条件。竞态要固定延迟、响应顺序、前后台切换或次数，必要时最小 A/B。未运行只能“候选复现路径/待验证”并写“按代码推导，待实测确认”。

局部低风险取触达文件 lint、直接测试、diff 检查；跨 owner、公共契约、异步生命周期、持久化、配置/生成物补对应合同、集成或专项门禁；Native、release、迁移、安全、身份、支付、隐私、数据丢失或核心主流程按项目要求补 build/export/smoke 或必要运行、网络、后台证据。专项门禁优先，不机械全量验证。

每个 I 须有证伪风险的验证点，含前提、输入/操作、Oracle、层级与状态；只写命令/测试名/通过不足。未执行、缺授权或覆盖不到的高层结果明确未验证，不因只读审查升级而擅自操作设备或外部系统。
