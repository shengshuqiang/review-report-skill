# API、Native 与埋点边界

执行链触达对应边界，或改动 Android/iOS 实现时读取。增量功能三类均给结论，但不机械要求三类都改动或验证。

每类标 `触达`、`不涉及（有依据）` 或 `证据不足`。触达项记录当前契约、本次允许变化、必须保护的原行为、风险和验证；不涉及项须给执行链依据。

## API（A）

仅冻结相关接口、请求方法/参数、响应字段/语义、空值/默认值、错误/取消、重试/幂等、分页/缓存和版本兼容。客户端意图不是后端契约，未改字段、错误语义及既有消费者默认不变。

门禁优先项目现有契约、mapper、错误分支或必要网络证据。客户端测试不证明服务端上线。

## Native（N）

冻结 JS/TS 到 package、adapter、bridge 或原生实现的入口、参数/返回值、事件、注册/权限、线程/生命周期、清理配对、双端差异和最低兼容范围。

改动 Android/iOS 实现时，沿共享入口或契约读取另一端 owner，对照触发条件、输入输出、正常/空值/错误/取消分支、状态/生命周期、副作用和用户结果。结论固定为：

- `一致`：契约和用户结果等价，有另一端文件/稳定符号与关键分支证据。
- `不一致（关联 P?）`：业务契约或用户结果无依据地不一致，另列独立问题。
- `有依据的平台差异`：有产品、平台 API 或现有架构依据。
- `不适用（无另一端同构能力）`：有明确能力/架构依据。
- `证据不足`：只看到一端、找不到 owner 或缺关键分支证据。

语言、库、结构不同不证明语义不同；只改一端须证明另一端不受影响、已有等价语义或有平台差异依据，不机械同步另一端，审查不赋予修改授权。

门禁按风险选 bridge 契约、双端关联测试、构建和必要设备证据。TypeScript 通过不证明原生契约正确，JS 调用不证明 Native 完成。

## 埋点（T）

冻结事件名、条件/时机/顺序、去重、属性名/类型、枚举/公共参数、用户/会话身份、归因和前后台边界；仅改埋点不得改变业务状态或流程。

优先 schema、时序、去重和属性验证。代码调用、SDK/bridge 接收、网络发出、平台入库分层陈述，声明后两者时才要求对应层级证据。

## 原行为与验证映射

使用 `A1/N1/T1 -> I1/I2 -> 验证门禁`，复用已有功能影响点 I，不另造原行为编号。只在相邻且有回归风险的场景列入口可达、正常结果、空值/错误、取消/重试、状态保留/清理、缓存/持久化、平台差异和埋点语义；不能只写“原功能不受影响”或扩展全产品回归。

门禁来自当前 owner 文档、脚本、测试或运行 Oracle，注明前提、输入/操作、可判定结果、层级和状态。结果为 `已满足/未满足/未验证/不适用/证据不足`。缺契约、原行为保护或匹配验证不能写已满足；不存在的脚本、未执行的门禁不能写已通过。
